# Trip photo storage and public delivery

Trip photos are stored on Laravel's `public` filesystem disk under `storage/app/public/trips/`.
The API exposes an absolute `photo_url` for each trip. That URL points to the same file through
`https://api.tiptrip.online/storage/...` when `APP_URL=https://api.tiptrip.online` is configured.

## Required production environment

Set these values in the backend `.env` file (do not commit `.env`):

```dotenv
APP_URL=https://api.tiptrip.online
APP_ENV=production
APP_DEBUG=false
```

The public disk URL is derived from `APP_URL`. After changing environment values, clear and rebuild
Laravel's cached configuration from the project root:

```bash
php artisan optimize:clear
php artisan config:cache
```

## Create and verify the public storage link

Run this once from the Laravel project root, as the deployment user:

```bash
php artisan storage:link
```

The expected link is:

```text
public/storage -> storage/app/public
```

Verify it:

```bash
ls -ld public/storage
readlink -f public/storage
```

The resolved path must end in `storage/app/public`. The PHP/web-server user must be able to read
files in `storage/app/public` and traverse the parent directories. Do not make the whole project
world-writable.

The web server's document root must point to the Laravel `public/` directory. The included
`public/.htaccess` handles Laravel routing on Apache when `mod_rewrite` and `AllowOverride All`
(or an equivalent override policy) are enabled. For Nginx, configure the site root to `public/`
and allow `/storage/` requests to resolve through the `public/storage` symlink.

## Verify a real uploaded image

1. Create a trip through the authenticated API and attach a real JPG or PNG image using the
   multipart field name `photo`.
2. Confirm the create response contains both `photo_path` and an absolute `photo_url`.
3. Copy the returned `photo_url` and request its headers:

   ```bash
   curl -I 'https://api.tiptrip.online/storage/trips/REPLACE_WITH_RETURNED_FILENAME'
   ```

   Expect HTTP `200` and an image content type such as `image/jpeg` or `image/png`.
4. Confirm the same trip's `photo_url` is present in both:
   - `GET /api/v1/public/trips`
   - `GET /api/v1/public/trips/{trip}`
5. Open the image URL in a private/incognito browser window. It must load without an API bearer token.

If the API response has a URL but the image request returns `404`, check the storage symlink, file
permissions, and web-server document root. If it returns `403`, check directory traversal/read
permissions and web-server access rules. If the URL has the wrong hostname, correct `APP_URL`, then
clear and rebuild the configuration cache.

## API contract

The `Trip` model appends `photo_url` to serialized trip responses. The URL is generated by the
configured `public` disk, so list, detail, create, update, and authenticated trip responses use the
same URL rule. Existing absolute photo URLs and legacy `storage/...` paths are tolerated.
